### Claude-Mem

Re-reads the scoped generation job under the same PostgreSQL row lock used by generation completion, evaluates the transition and updates state within one transaction. Queue operations and audit publication occur after that transaction.

Committed PostgreSQL integration fixtures use isolated schemas, real row locks, gated concurrent requests and lock-wait inspection. They cover retry conflicts after processing or completion, duplicate retries, cancellation racing with completion and simultaneous cancellations.

The integration suite requires CLAUDE_MEM_TEST_POSTGRES_URL and skips when it is absent. No database-backed test was executed during this review. Queue I/O remains outside the row-lock transaction.

**[#5649](https://github.com/thedotmack/claude-mem/pull/5649) — Reject newer-schema restore snapshots before replacing the healthy live database** · merged 2026-11-10 05:52 · [`c141e54`](https://github.com/thedotmack/claude-mem/commit/c141e5416b18070b445c5c84fb6c1c9676106ef9)

Checks the staged snapshot's PRAGMA user_version against LATEST_SCHEMA_VERSION in the SQLite file-job process before checkpointing or backing up the live database. The staged WAL participates in the compatibility check.

Committed SQLite fixtures verify rejection preserves the live and snapshot bytes, creates no pre-restore copy, leaves a failed pending restore recoverable by the worker and detects a newer schema stamp in the WAL. Older, current and unstamped snapshots remain accepted.

The preflight checks the schema version stamp and existing SQLite integrity path. This review inspected the fixtures and did not run the restore suite.

**[#5647](https://github.com/thedotmack/claude-mem/pull/5647) — Schedule replica-vector cleanup after committed remote deletions and earlier writes finish** · merged 2026-11-10 05:45 · [`d58a11d`](https://github.com/thedotmack/claude-mem/commit/d58a11df4755df02881345ec47d9712e673f2ebd)

Captures the replica's local row ID before deleting a tombstoned origin record, dispatches cleanup only after the SQLite transaction commits and orders it after earlier writes for that row. Local and replicated deletions share a serialized cleanup lane.

Committed fixtures cover observations, summaries and prompts, assert the replica row ID and matching document type, delay an earlier write to test ordering, discard cleanup on rollback and verify a simulated vector-service failure preserves durable sync progress and permits later cleanup.

Vector cleanup is best effort. Failures are logged and durable synchronization continues, so a failed vector-service deletion can leave fragments until a later cleanup. Tests use an in-memory SQLite store and a simulated vector client, and were not rerun.
